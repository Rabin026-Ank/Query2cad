# Query2CAD

## Abstract
Computer Aided Design (CAD) engineers typically do not achieve their best prototypes in a single attempt. Instead, they iterate and refine their designs to achieve an optimal solution through multiple revisions. This traditional approach, though effective, is time-consuming and relies heavily on the expertise of skilled engineers. To address these challenges, we introduce Query2CAD, a novel framework to generate CAD designs. The framework uses a large language model to generate executable CAD macros. Additionally, Query2CAD refines the generation of the CAD model with the help of its self-refinement loops. Query2CAD operates without supervised data or additional training, using the LLM as both a generator and a refiner. The refiner leverages feedback generated by the BLIP2 model, and to address false negatives, we have incorporated human-in-the-loop feedback into our system. Additionally, we have developed a dataset that encompasses most operations used in CAD model designing and have evaluated our framework using this dataset. Our findings reveal that when we used GPT-4 Turbo as our language model, the architecture achieved a success rate of 53.6% on the first attempt. With subsequent refinements, the success rate increased by 23.1%. In particular, the most significant improvement in the success rate was observed with the first iteration of the refinement. With subsequent refinements, the accuracy of the correct designs did not improve significantly.

## How to run the system

1. Download and set up the [FreeCAD](https://github.com/FreeCAD/FreeCAD) software.

2. Clone the repository.
```
git clone https://github.com/Rabin026-Ank/Query2cad.git
```

3. Install the dependencies.
```
pip install -r requirements.txt
```

4. Copy `.env.example` to `.env` and fill in the path to FreeCAD and the API keys
you intend to use.
```ini
FREECAD_CMD=D:\FreeCAD\bin\freecadcmd.exe
ORNITH_BASE_URL=https://your-endpoint/v1
ORNITH_API_KEY=...
GEMINI_API_KEY=...
```

5. Run the system from the repository root.
```
python src/run.py --mode single
python src/run.py --mode dataset --code_gen_model ornith --reasoning_model ornith --vqa_model ornith
```

6. The results are stored in the results/ folder and new queries can be added in data/queries.txt

## Models

Pick a model per role with `--code_gen_model`, `--reasoning_model` and `--vqa_model`.
The backend is chosen from the name:

| Name | Backend | Notes |
| --- | --- | --- |
| `ornith`, or any other unrecognised name | The OpenAI-compatible server at `ORNITH_BASE_URL` | Text and images. The default. |
| `gemini`, `gemini-2.5-flash`, `gemini-2.5-pro`, ... | Google AI Studio | Text and images |
| `gpt4-turbo`, `chatgpt` | OpenAI (`PROXY_API_KEY`) | Text only; used in the paper. Needs `pip install openai` |
| `codellama`, `llama3` | Together AI (`TOGETHER_API_KEY`) | Text only; used in the paper |

`--vqa_model` grades the render and captions it, so it has to be a model that
accepts images: `ornith` and the `gemini-*` models both do.

Other useful arguments: `--vqa_threshold` (default 0.9), `--error_iterations`
(default 3), `--refine_iterations` (default 3), `--human_feedback True`, and
`--query` to pass a single query without being prompted for it.

## Running without a GPU

The published system drove the FreeCAD window with pyautogui and ran BLIP2
flan-t5-xxl and t2v_metrics VQAScore locally, which together need a 1920x1080
screen and roughly 30 GB of VRAM. Two components are replaced so the same
algorithm runs on an ordinary machine. The prompts in `src/prompts.py`, the
refinement loop and the command line are unchanged.

| Original | Replacement |
| --- | --- |
| pyautogui typing into the FreeCAD window, screenshotting a fixed screen region and reading errors off the clipboard | `src/freecad_runner.py` and `src/_fc_driver.py` run each macro inside `freecadcmd`, capture the isometric view and return a structured error |
| BLIP2 flan-t5-xxl captions | The vision model named by `--vqa_model` |
| t2v_metrics VQAScore (clip-flant5-xl) | The same vision model, asked to score the render from 0 to 1 |

`utils.gui_sequence`, `utils.get_captions` and `utils.get_vqa_score` keep their
original names and signatures, so the flow in `src/run.py` reads as it did before.

## Files

| File | Role |
| --- | --- |
| `src/run.py` | Entry point and the top-level loop |
| `src/utils.py` | Macro execution, error repair, refinement, scoring, captioning |
| `src/llm.py` | All model backends, text and image |
| `src/prompts.py` | The prompts, unchanged |
| `src/freecad_runner.py` | Runs a macro in `freecadcmd` and returns errors or a render |
| `src/_fc_driver.py` | Executes inside FreeCAD: runs the macro, captures the isometric view |

Headless rendering needs three things in order, all handled in `_fc_driver.py`:
`FreeCADGui.showMainWindow()`, a realised main window, and a pumped Qt event queue
before `saveImage`. Without the event pump every capture silently comes out as a
flat top view, whatever the camera was set to.
